# ADR 0017: Pivot de UI a composición cinemática 16:9 (supersede parcial de ADR 0016)

El usuario aportó dos capturas de referencia aprobadas (PoC diálogo e interacción): fondo ilustrado ocupando casi todo el canvas, barra de progreso de misión + objetivo actual arriba, panel inferior con retrato busto (cabeza/hombros) + texto, y para interacción un menú de acciones a la derecha con el objeto resaltado en la escena mediante corchetes de esquina. Esto contradice explícitamente ADR `0016-logical-resolution-integer-scaling.md`, que fijaba una estética pixel-art de grilla lógica 320×180 con `TEXTURE_FILTER_POINT` global — las capturas muestran iluminación e ilustración de alto detalle, no pixel art.

## Decisión

1. **Filtrado**: se elimina `TEXTURE_FILTER_POINT` como default global de `AssetStore::texture()`. El filtro pasa a ser un parámetro (`TEXTURE_FILTER_BILINEAR` por defecto), reservando `TEXTURE_FILTER_POINT` explícito solo para assets declarados como pixel-art intencional (ninguno está wireado en el flujo activo hoy — los crops de `pixel-cyberpunk-interior` son referencia sin conectar, ver `docs/asset-integration-style.md`). Esto reemplaza la regla "point filtering en todo el gameplay" de ADR `0016`/`AGENTS.md` §5, que ya no aplica al flujo narrativo principal.
2. **Resolución**: se mantiene el canvas de 1280×720 (`GameApp::W/H`) — ya es 16:9, calza con el "equivalente documentado" que la propia consigna permite, y evita reescribir las coordenadas de `WorldLayout`/tests que ya están en ese espacio. Lo que sí cambia es que las pantallas dejan de vivir en cajas pequeñas centradas con márgenes negros grandes (el problema real reportado como "muy chico, con espacio sin usar") — los paneles pasan a ocupar casi todo el canvas (ver `UiMetrics` en `src/ui/widgets/UiMetrics.hpp`).
3. **Layout compartido**: toda pantalla de misión usa una franja superior con `NodeMapView` (barra de progreso — ya implementada en ADR previo, ahora reposicionada full-width) a la izquierda/centro y un nuevo `CurrentObjectivePanel` a la derecha, más un panel inferior dividido en retrato + contenido, en vez de un único cuadro centrado.
4. **Retratos**: `PortraitFrame` nuevo, pensado para bustos cabeza/hombros. **Gap real, no oculto**: no existen todavía assets de retrato recortados en ese encuadre — se sigue usando el sprite `character.*.idle` de cuerpo completo como placeholder hasta que exista un retrato dedicado (ver sección de assets pendientes en `docs/mission-screen-templates.md`). Esto no cumple el criterio de aceptación "portraits are head-and-shoulders only" todavía; queda documentado como pendiente, no simulado.
5. **Fondos cinemáticos**: tampoco existen ilustraciones de fondo full-frame. `CinematicScenePanel` reutiliza el shell procedural existente (`drawShelterShell`/`drawExteriorShell`) escalado a ocupar el área de escena, hasta que haya arte real — mismo principio que el resto del proyecto (texto/procedural en vez de placeholder falso presentado como terminado).

## Consecuencias

- Los widgets nuevos de esta sesión (`StoryPanel`, `ChoicePanel`, `DialoguePanel`, etc.) se actualizan para consumir texturas con el filtro que les pase el llamador en vez de asumir point-filter; no se reescriben desde cero.
- `docs/asset-integration-style.md` y `docs/static-art-direction.md` quedan desactualizados en su sección de filtrado para el flujo narrativo — actualizar en el mismo cambio.
- El sistema de resaltado de objetos (corchetes de esquina) requiere coordenadas de hotspot por nodo; se reutilizan los `bounds`/`pivot` ya existentes en `WorldProp` (`WorldLayout.hpp`) en vez de introducir un nuevo formato de datos.
